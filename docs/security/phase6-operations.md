# フェーズ 6 防御の運用手順

この文書は、フェーズ 6 で作った検知・遮断の部品を安全に動かすための手順です。
**今の状態：コードは完成していますが、実際のソフトの導入と承認はまだです。本番の防御は完了していません。**
`pnpm --filter api security:status` と `scripts/doctor.sh` が、導入されていない部品を一つずつ正直に表示します。
未設定・未知・observe（観測のみ）・test のままの部品が一つでもあれば「INCOMPLETE」と表示します。

## 導入の順番

1. 監査の土台（Task 1・8）：イベントの記録と、Object Lock への配送・検証
2. 入口の遮断（Task 2）：エッジの gate と接続の管理
3. 復旧の口（Task 9）：通知、異議申し立て、運営者による解除
4. 各検知器（Task 3〜7）：Falco、metrics とプロキシ、Safe Browsing、IP データ、罠
5. 結合の確認（Task 11）

各検知器は `test`（試験）→ `observe`（観測だけ。止めない）→ `enforce`（実際に止める）の順に上げます。
本番では `test` を設定できません。

## 承認が必要なものの一覧

ソフトの取得、適用、有料契約、外部への送信、解除できない保持は別々に承認します。
一つ承認しても、ほかの項目の承認にはなりません。

| 項目 | Task | 区分 |
| --- | --- | --- |
| Falco 本体、syscall ルール、Linux ドライバ、収集コンテナ（固定バージョン）と権限 | 3 | 取得・適用 |
| 本番の共有リプレイストアと、実行環境からの識別リゾルバ、非公開 listener の接続 | 3 | 適用 |
| metrics 収集器と必須の外向きプロキシ（固定イメージ・権限） | 4 | 取得・適用 |
| 外向き NetworkPolicy の適用（迂回拒否を実機で確認してから enforce） | 4 | 適用 |
| IP 匿名化データ（MaxMind / IPinfo）、Tor 出口一覧、学校・iCloud Private Relay・Cloudflare bot の一覧 | 6 | 有料契約・外部送信・取得 |
| （任意）MMDB を読む npm パッケージ。固定バージョンと lockfile の差分を先に提示 | 6 | 取得 |
| PostgreSQL 監査拡張（pgAudit など）、ログ収集器、罠テーブルの migration | 7 | 取得・適用 |
| 罠の値の生成・登録・配置 | 7 | 適用 |
| 外部 URL 検査（Safe Browsing）の規約・認証情報・公開 URL の送信 | 5 | 外部送信 |
| Object Lock 対応ストレージ（リージョン・保持期間・費用）、書き込み専用と読み取り専用の認証情報 | 8 | 有料契約・外部送信・**解除できない保持** |
| 本番 DB への migration 0030〜0033 の適用 | 1〜9 | 適用 |

Object Lock の COMPLIANCE 保持は、始めると途中で短縮も削除もできません。保持期間と費用を先に決めてください。
同じ一覧は `packages/shared` の `APPROVAL_LIST` にもあり、テストで文書と一致を確認しています。

## 設定値

管理画面（owner のみ）の設定から変更します。変更前後の値は監査記録に残ります。
未知のキー、負数、0、上限を超える値（無制限を含む）は拒否されます。

| キー | 初期値 | 意味 |
| --- | --- | --- |
| `security.window_ms` | 60000 | 集計する時間窓（ミリ秒） |
| `security.min_samples` | 3 | 時間窓で必要な最小サンプル数 |
| `security.max_gap_ms` | 30000 | サンプル間の許容する欠け。時間窓以下 |
| `security.threshold.cpu` | 0.8 | CPU の通知しきい値。CPU だけでは通知のみ |
| `security.threshold.egress_bytes` | 104857600 | 時間窓あたりの外向き通信量 |
| `security.threshold.connections` | 1000 | 同時接続数 |
| `security.threshold.served_bytes` | 104857600 | 時間窓あたりの配信量（イベントの増枠で倍率がかかる） |
| `security.scan.window_ms` / `security.scan.threshold` | 300000 / 5 | 罠パスへの走査を数える窓と回数 |
| `security.network.max_age_hours` | 168 | IP データの更新期限。超えると unknown 扱いで、保護対象の操作は 503 |
| `security.network.exceptions` | 空 | 例外 CIDR。VPN 判定だけに効き、罠や攻撃 IP のブロックには効かない |
| `security.audit.max_delivery_delay_s` | 300 | 監査の配送遅延の許容。超えると警告し、公開と巻き戻しを保留 |
| `security.outbox.capacity` | 10000 | 未配送 outbox の許容件数 |
| `security.notify.operator_to` | 空 | 運営者への通知先メールアドレス |
| `security.detector.<名前>.mode` | observe | `falco` `metrics_proxy` `network` `honeytokens` `safe_browsing` のモード |

注意：検知器が実行時にこれらの値を読む配線は Phase 8 の配備で行います。それまでは既定値がコード側に入っています。

## 手順

### 罠の生成・入れ替え・失効
- 罠の値は、承認済みの配備でだけ生成します。リポジトリや台帳に値を書きません（保存されるのは HMAC のみ）。
- 入れ替えは、新しい値を登録してから古い値の有効期限を切ります。値の取り違えを避けるため、同時に有効にするのは移行の間だけです。
- 失効した値が使われた場合は「失効済み」として扱い、通知だけにします。

### 誤検知の解除
1. 管理画面（Tailscale 経由）で事件を開き、理由を確認します。
2. 解除は「その事件の理由」だけを外します。ほかの停止理由（手動停止、容量超過、別の事件）が残っていれば、アプリは起動しません。
3. アカウント凍結の解除は、既存の 24 時間予約だけで行います。事件の解除では迂回できません。

### 停止に失敗したとき
- 停止要求は outbox に残り、再試行されます。止まっていない間は gate 側の遮断が効きます。
- 失敗が続く場合は、運営者がコンテナ名を確認して手動停止します。**証拠やデータは削除しません。**

### 検知器が止まったとき
- センサーの健康状態は未導入／期限切れ／欠測として表示されます。欠測は「安全」ではなく「不明」です。
- 不明の間は止める判断をしません。復旧するまで観測と通知だけを続け、運営者に知らせます。

### S3（Object Lock）への配送失敗
- 未配送の監査行は DB の鎖に残り、再配送されます。同じ範囲は同じバッチ ID で重複しません。
- 遅延が基準を超えると、公開・巻き戻し・管理者の変更を保留します。既存の配信と停止は止めません。
- 認証情報の失効や容量の問題は、運営者が承認済みの手順で直します。

### checkpoint の不一致
- `pnpm --filter api security:verify-audit` で範囲ごとの検証を行います（読み取り専用の認証情報を使用）。
- 改ざん・欠番・末尾の切り詰め・古い DB からの復元・保持設定の違いは、コードで表示されます。
- 不一致のときは**書き換えも削除もしません**。DB と WORM の両方をそのまま保存し、原因を調べてから運営者が判断します。

### 緊急時
- 証拠とデータを削除しません。運営者の認証経路（Tailscale、パスキー昇格）は止めません。
- 管理画面に入れない場合も、サーバー上の端末からのスクリプトで復旧できる経路を維持します。
